## 핵심 요약

- GitHub App 연결은 설치 대상 저장소를 선택할 수 있지만, 사용자 인증과 설치는 서로 다른 설정입니다.
- 현재 Claude Code 클라우드에는 GitHub App 외에 로컬 `gh` 토큰을 연결하는 방식도 있습니다. 실제 인증 경로부터 확인해야 합니다.
- 목록에 보이는 것, 공개 코드를 읽는 것, 비공개 저장소를 읽는 것, 원본에 쓰는 것은 서로 다른 권한입니다.

## 먼저 어떤 방식으로 연결했는지 확인하기

“Claude Code를 GitHub에 연결했다”는 말만으로 권한 범위를 알 수는 없습니다. 2026년 10월 17일 공식 안내는 클라우드 연결 방식으로 GitHub App과 `/web-setup`을 구분합니다.[1]

| 환경·연결 | 먼저 확인할 항목 |
| --- | --- |
| 클라우드의 GitHub App 연결 | 설치 계정, 선택 저장소, App 권한 |
| 클라우드의 `/web-setup` 연결 | 전달한 `gh` 토큰의 접근 범위 |
| 로컬 실행 | Git·`gh` 인증, SSH 키, credential helper 등 |

특히 `/web-setup`으로 연결한 토큰은 App이 설치되지 않은 저장소에도 토큰의 권한 범위에서 접근할 수 있습니다. 따라서 App 설정만 줄였다고 모든 인증 수단이 제한되는 것은 아닙니다.

## Authorize와 Install은 무엇이 다를까?

GitHub App의 **Authorize**는 사용자 계정에 대한 인증·권한 부여이고, **Install**은 특정 계정이나 조직의 리소스에 App을 설치하는 과정입니다. 같은 App이 `Authorized GitHub Apps`와 `Installed GitHub Apps`에 각각 나타날 수 있습니다.[2]

인증 화면의 “Verify your GitHub identity”, “Know what resources you can access”, “Act on your behalf”는 GitHub App 사용자 인증에서 사용하는 설명입니다. `Authorize`는 단순한 로그인 확인만이 아니라, 허용된 정보 조회나 사용자 대신의 동작과도 관련됩니다.

한편 `Authorized OAuth Apps`는 별도 구분입니다. 실제 앱 유형과 권한을 설정 화면에서 확인해야 하며, 문구 하나만으로 접근 범위를 모두 확정하지는 않는 편이 좋습니다.

## App 설치 범위를 바꾸는 방법

개인 계정에 설치한 App은 다음 경로에서 확인할 수 있습니다.[3]

1. GitHub의 **Settings → Applications → Installed GitHub Apps**로 이동합니다.
2. 해당 Claude App의 **Configure**를 엽니다.
3. **Repository access → Only select repositories**를 선택합니다.
4. 허용할 저장소를 지정하고 **Save**합니다.

처음 설치할 때도 저장소 선택을 지원하는 App이라면 설치 화면에서 범위를 정할 수 있습니다.[4] 조직 저장소는 해당 조직의 App 설치와 승인 정책을 따로 확인해야 합니다.

이 설정은 **해당 App 설치가 접근하는 저장소 범위**를 바꿉니다. 다른 계정·조직에 설치한 App이나 별도 토큰의 권한까지 한 번에 바꾸는 설정은 아닙니다.

## 선택하지 않은 저장소가 목록에 보이면 제한 실패일까?

목록만 보고 판단할 수는 없습니다. 클라이언트가 어떤 경로로 목록을 구성했는지, 공개 저장소인지, 별도 토큰 연결이 있는지를 함께 봐야 합니다.

현재 Claude 공식 안내는 GitHub App 방식에서도 공개 저장소를 읽을 수 있다고 설명합니다.[1] 공개 코드를 읽었다는 사실이 원본 저장소에 push할 권한까지 있다는 의미는 아닙니다.

| 확인한 사실 | 그것만으로 확정할 수 없는 것 |
| --- | --- |
| 저장소 이름이 목록에 표시됨 | 비공개 내용 읽기·쓰기 가능 여부 |
| 공개 저장소를 clone함 | 원본 저장소에 push 가능 여부 |
| 비공개 내용을 읽음 | 어느 인증 수단이 사용됐는지 |
| 새 브랜치로 push함 | 다른 모든 저장소의 권한까지 동일한지 |

GitHub App의 사용자 권한과 설치 권한은 구분해서 관리됩니다.[2] 다만 이를 “모든 API의 모든 접근이 선택 저장소의 단순 교집합”이라고 넓게 표현하면 공개 리소스나 별도 인증 경로를 놓칠 수 있습니다.

## 로컬 CLI에서는 토큰만 바꾸면 충분할까?

Fine-grained PAT는 저장소와 권한을 좁히는 수단입니다. 하지만 `gh`용 토큰을 제한하더라도 `git`이 다른 credential helper나 SSH 키를 사용하면 다른 권한이 남을 수 있습니다. 실제로 사용하는 경로를 모두 검토해야 합니다.

확인할 때는 토큰 값을 출력하거나 채팅에 붙여 넣을 필요가 없습니다. 계정 설정의 토큰 범위와 도구의 인증 상태, Git 원격 접속 방식을 확인하면 됩니다. 에이전트의 명령 허용·차단 규칙도 보조 수단이지만, 그것만으로 자격 증명의 범위가 바뀌지는 않습니다.

## 실제 확인은 어떻게 할까?

설치 설정과 토큰 연결 방식을 먼저 확인하고, 필요하면 직접 만든 테스트 저장소에서 읽기와 쓰기를 구분해 검증하세요. 업무 저장소에 임의 변경을 만들며 확인할 필요는 없습니다.

접근이 안 된다고 App을 바로 삭제·재설치할 필요도 없습니다. 조직 승인, 연결 계정, 설치 범위, 토큰 방식 등을 확인한 뒤 현재 공식 문제 해결 안내를 따르는 편이 좋습니다. 과거 이슈 번호 하나를 모든 환경의 원인으로 적용하지는 않아야 합니다.
