## 핵심 요약

- 매개변수나 지역 변수가 같은 이름의 필드를 가리면 변수 섀도잉이라고 부릅니다.
- 자식 클래스가 상속받을 필드와 같은 이름의 필드를 선언하는 경우는 Field Hiding, 즉 필드 숨김으로 구분합니다.
- 필드 접근은 오버라이드된 인스턴스 메서드처럼 실행 중 객체 타입에 따라 선택되지 않습니다.

## Shadowing은 공식 용어일까?

Java Language Specification(JLS) §6.4.1은 Shadowing을 정의합니다. 단순 이름으로 변수를 참조할 때, 같은 이름의 다른 선언 때문에 기존 선언을 가리킬 수 없게 되는 경우가 포함됩니다.[1]

한국어 기술 문서에서는 “변수 그림자”보다는 **변수 섀도잉**, “매개변수가 필드를 가린다”라는 표현이 상황을 전달하기 좋습니다. 상속 관계의 필드 숨김은 JLS §8.3에서 따로 다룹니다.[2]

## 하나의 예제로 비교하기

다음은 `ShadowingDemo.java` 전체 코드입니다. Java 17에서 실행할 수 있습니다.

```java
public class ShadowingDemo {
    static class Parent {
        String name = "parent";
    }

    static class Child extends Parent {
        String name = "child";

        void show(String name) {
            System.out.println(name);
            System.out.println(this.name);
            System.out.println(super.name);
        }
    }

    public static void main(String[] args) {
        Child child = new Child();
        child.show("parameter");

        Parent parentView = child;
        System.out.println(parentView.name);
        System.out.println(child.name);
    }
}
```

출력은 다음과 같습니다.

```text
parameter
child
parent
parent
child
```

## 매개변수 name과 this.name

`show()` 안의 `name`은 매개변수입니다. 매개변수 선언이 같은 이름의 필드를 가리기 때문에 단순 이름 `name`은 필드를 선택하지 않습니다.

`this.name`은 현재 객체를 기준으로 `Child`에 선언된 필드를 참조합니다. 생성자나 setter에서 흔히 보는 다음 코드도 같은 원리입니다.

```java
void setName(String name) {
    this.name = name;
}
```

오른쪽은 전달받은 값이고 왼쪽은 객체의 필드입니다. 섀도잉 자체가 오류인 것은 아닙니다. 다만 `name = name;`이라고 쓰면 매개변수를 자기 자신에게 대입하므로 필드가 바뀌지 않습니다.

## Child.name과 Parent.name은 별도의 필드다

`Child`의 `name` 선언은 부모에서 상속될 같은 이름의 필드를 숨깁니다. 부모 필드가 자식 필드로 교체되는 것은 아닙니다. 예제의 객체에는 각각의 선언에 해당하는 상태가 존재합니다.

`super.name`으로 부모 쪽 필드를 명시해서 접근할 수 있습니다. 이 설명은 예제처럼 부모 필드에 접근할 수 있는 경우를 전제로 합니다. 부모의 `private` 필드를 자식에서 `super`로 직접 읽을 수 있다는 뜻은 아닙니다.

JLS는 필드 숨김에서 `static`과 인스턴스 필드를 모두 다룹니다.[2] 메서드의 오버라이딩·정적 메서드 숨김 규칙과 혼동하지 않는 것이 좋습니다.

## 같은 객체인데 참조 타입에 따라 값이 달라진다

예제에서 `parentView`와 `child`는 같은 객체를 가리킵니다. 그런데 `parentView.name`은 `Parent`의 필드, `child.name`은 `Child`의 필드를 선택합니다.

이는 **필드 접근이 참조 표현식의 컴파일 시점 타입을 기준으로 결정되기 때문**입니다.[3] 오버라이드된 인스턴스 메서드를 호출할 때의 동적 디스패치와 다릅니다.

이 차이 때문에 상속 계층에서 같은 이름의 필드를 중복 선언하면 읽는 사람의 예상과 실제 동작이 어긋날 수 있습니다. 의도한 설계가 아니라면 이름을 구분하거나 접근 메서드로 계약을 명확히 하는 편이 좋습니다.

## 지역 변수는 중첩 블록이면 마음대로 중복 선언할까?

Java에서는 바깥 지역 변수의 범위 안에서 같은 이름의 지역 변수를 단순 중첩 블록에 다시 선언할 수 없습니다.[1] 다음은 **컴파일 오류를 설명하기 위한 예제**입니다.

```java
void invalid() {
    int count = 1;
    {
        int count = 2; // 컴파일 오류: 같은 범위에 이미 선언된 지역 변수
    }
}
```

따라서 다른 언어의 “안쪽 블록 변수가 바깥 변수를 가린다”는 예제를 Java에 그대로 옮겨서는 안 됩니다. 지역 클래스 등 별도의 선언 맥락에 관한 규칙도 있으므로, 여기서는 일반적인 메서드의 중첩 블록을 구분해 기억하면 됩니다.
