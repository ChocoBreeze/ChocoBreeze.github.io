# 38. 외부 링크 생존 리포트

글 본문의 외부 링크에 실제로 요청을 보내 끊긴 링크 목록을 만드는 수동 진단 명령을 추가합니다.

## 현재 동작

- 22번 계획과 `check:build-artifacts`는 내부 링크만 검사합니다. 22번 문서에 "외부 링크의 네트워크 생존 여부는 검사하지 않음"이라고 명시되어 있습니다.
- 2026-10-28 원본 Markdown(frontmatter 제외) 측정값은 다음과 같습니다.
  - 외부 링크 4,887개, 중복 제거 1,896개 URL, 380개 도메인
  - 카테고리별: Market Brief 3,462, Reports 597, ETF 586, Programming 144, Problem Solving 87, Computer Science 8, Lifestyle 3
  - 도메인 상위: reuters.com 340, sec.gov 214, leetcode.com 86, youtube.com 51, apnews.com 51, finance.yahoo.com 43, wsj.com 39
- 상위 도메인 다수(Reuters, SEC, WSJ, Barron's 등)는 자동 요청을 401·403·429로 막는 경우가 많습니다. 이런 응답은 링크가 끊겼다는 뜻이 아닙니다.

## 목표

1. 확실히 끊긴 링크(404·410, 도메인 없음, 연결 거부)를 다른 응답과 구분해 보여줍니다.
2. 외부 사이트에 부담을 주지 않습니다.
3. 외부 사이트 상태가 빌드나 배포를 막지 않습니다.

## 범위

- `npm run report:links` 수동 명령
- 링크 추출과 응답 분류 함수, 로컬 테스트 서버를 쓰는 단위 테스트
- 포함하지 않음: CI·배포 워크플로 연결, 예약 실행, 링크 자동 수정, 결과 캐시

## 설계

### 링크 추출

- 대상은 `src/content/blog/`의 글 본문입니다. frontmatter와 코드(펜스 블록, 인라인 코드) 안의 주소는 링크가 아니므로 제외합니다.
- Markdown 링크 `[텍스트](주소)`, 꺾쇠 자동 링크 `<주소>`, 맨 주소(GFM 자동 링크), HTML `href="주소"`를 모두 찾습니다.
- 같은 주소는 한 번만 요청하고, 결과에는 그 주소를 쓴 모든 글과 줄 번호를 붙입니다.
- 초안 글도 포함합니다. 발행 전에 고칠 수 있기 때문입니다.

### 요청

- `HEAD`로 먼저 요청하고, `405`·`501`이나 일부 서버가 `HEAD`에 주는 `403`·`404`이면 `GET`으로 한 번 더 확인합니다. `GET`은 응답 헤더만 받고 본문은 읽지 않습니다.
- 리다이렉트는 따라가고 최종 주소를 기록합니다.
- 요청 제한: 전체 동시 요청 8개, 같은 도메인은 한 번에 1개와 요청 간 500ms 간격, 요청당 제한 시간 15초입니다.
- User-Agent는 사이트 주소를 밝히는 고정 문자열을 씁니다. 개인 연락처는 넣지 않습니다.

### 분류

| 분류 | 조건 | 의미 |
| --- | --- | --- |
| 끊김 | 404, 410, 도메인 없음(DNS 실패), 연결 거부 | 고쳐야 할 가능성이 높음 |
| 확인 필요 | 401, 403, 429, 5xx, 시간 초과, 기타 네트워크 오류 | 봇 차단이나 일시 장애일 수 있어 사람이 확인 |
| 이동 | 최종 응답 2xx, 다른 도메인으로 리다이렉트 | 링크는 살아 있으나 주소 갱신을 고려 |
| 정상 | 2xx(같은 도메인 안의 리다이렉트 포함) | 출력하지 않고 개수만 표시 |

### 출력

- 분류별로 묶어 주소, 상태, 사용한 글과 줄 번호를 출력하고 끝에 개수를 요약합니다.
- `--json`으로 같은 내용을 JSON으로 출력합니다.
- `--category <이름>`으로 카테고리를 좁힙니다. 전체 실행은 수 분이 걸리므로 부분 점검용입니다.
- 종료 코드는 항상 0입니다. 1은 잘못된 옵션일 때만 씁니다.

### 실행하며 고친 것

- **각주가 붙은 링크 오탐**: `[출처](주소)[^2]`에서 `)[^2]`까지 주소로 읽어 멀쩡한 링크 19개가 404로 보고됐습니다. 주소 안에서 짝이 없는 `)`·`]`가 나오면 그 앞에서 자르도록 고쳤습니다.
- **리다이렉트 반복**: 쿠키를 요구하며 같은 주소로 되돌려 보내는 VanEck 문서 4개가 `TypeError`로만 표시됐습니다. `REDIRECT_LOOP`로 표시합니다(분류는 확인 필요).
- **자동 요청에 404를 주는 사이트**: `acmicpc.net`은 확실히 있는 1000번 문제에도 404를 돌려줍니다. 이 사이트의 404는 끊김이 아니라 확인 필요로 분류합니다(`UNRELIABLE_NOT_FOUND_HOSTS`).
- 브라우저 User-Agent를 흉내 내 차단을 피하는 방식은 쓰지 않습니다. 차단 응답은 그대로 확인 필요로 남깁니다.

## 테스트 설계

- 추출: 코드 블록·인라인 코드·frontmatter 안의 주소 제외, 문장부호로 끝나는 맨 주소 정리, 줄 번호
- 분류: 로컬 서버의 200, 301(같은 호스트·다른 호스트), 403, 404, 410, 500, 시간 초과, `HEAD` 405 후 `GET` 200
- 같은 도메인 요청이 동시에 하나만 나가는지
- 테스트는 외부 네트워크에 접속하지 않습니다.
