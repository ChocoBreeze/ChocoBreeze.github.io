# 37. 이어 읽기 위치 기억

긴 글을 중간까지 읽고 떠난 독자가 다시 왔을 때, 읽던 위치로 돌아갈 수 있는 안내를 보여줍니다.

## 현재 동작

- 글 페이지(`BlogPost.astro`)의 스크립트는 `.post-body` 기준 읽기 진행률(0~1)을 계산해 상단 진행 표시줄에 씁니다(`updateReadingProgress`).
- 목차 링크와 본문 제목(`h2`·`h3` 등)을 연결해 현재 위치의 목차 항목을 강조합니다.
- 브라우저 저장소(`localStorage`)는 테마 선택(`theme`)에만 씁니다.
- 다시 방문하면 항상 글의 처음부터 보입니다. 브라우저의 뒤로 가기는 스크롤을 복원하지만, 새로 방문하면 복원하지 않습니다.

## 목표

1. 긴 글을 중간까지 읽었다면, 다음 방문 때 "이어 읽기"를 한 번의 클릭으로 제안합니다.
2. 자동으로 스크롤하지 않습니다. 독자가 선택합니다.
3. 저장 실패나 JavaScript 미실행이 글 읽기를 방해하지 않습니다.

## 범위

- 글 상세 페이지의 위치 저장과 이어 읽기 안내
- 순수 함수 모듈과 단위 테스트, 브라우저 테스트
- 포함하지 않음: 기기 간 동기화, 읽은 글 목록이나 진행률 표시, 서버 저장

## 설계

### 저장

- 키 하나(`reading-positions`)에 `{ [경로]: { progress, heading, savedAt } }` 형태로 저장합니다.
  - `progress`는 기존 진행 표시줄과 같은 0~1 값입니다.
  - `heading`은 현재 위치 직전 제목의 텍스트로, 안내 문구에만 씁니다.
- 진행률이 10% 미만이면 저장하지 않습니다. 다시 방문해 페이지 맨 위에 있는 순간 기존 기록을 덮어쓰지 않기 위해서입니다.
- 진행률이 95% 이상이면 다 읽은 것으로 보고 기록을 지웁니다.
- 스크롤 중에는 1초에 한 번 이하로 저장하고, 페이지를 떠날 때(`pagehide`) 한 번 더 저장합니다.
- 최근 30개 글만 남기고, 90일이 지난 기록은 버립니다.
- 저장소 접근은 모두 `try/catch`로 감쌉니다. 사생활 보호 모드 등에서 실패해도 아무 일도 일어나지 않습니다.

### 안내 표시 조건

다음을 모두 만족할 때만 화면 아래에 안내를 띄웁니다.

- 이 글의 기록이 있고 90일 이내입니다.
- 기록된 진행률이 10% 이상 95% 미만입니다.
- 주소에 `#`이 없습니다. 특정 제목으로 바로 들어온 방문을 방해하지 않기 위해서입니다.
- 현재 스크롤이 페이지 맨 위 근처입니다. 뒤로 가기로 브라우저가 이미 위치를 복원했다면 띄우지 않습니다.
- 글이 화면 높이의 세 배보다 깁니다.

### 안내 UI

- 문구는 "읽던 위치가 있습니다", 제목이 있으면 "· <제목>"을 덧붙입니다. 버튼은 "이어 읽기"와 닫기(×) 두 개입니다.
- "이어 읽기"를 누르면 저장된 진행률 위치로 스크롤하고 안내를 닫습니다. 닫기를 누르면 이번 방문 동안만 숨깁니다.
- 독자가 직접 스크롤해 저장된 위치에 이르면 안내를 자동으로 닫습니다.
- 마크업은 서버에서 `hidden` 상태로 렌더링하고, 조건을 만족할 때만 스크립트가 표시합니다.
- 화면 아래 가운데에 고정하고, 맨 위로 버튼과 겹치지 않게 합니다. 인쇄에서는 숨깁니다.

### 코드 구성

- 저장 형식, 정리, 표시 조건 판단은 `src/lib/readingPosition.mjs`의 순수 함수로 둡니다.
- DOM 연결은 `BlogPost.astro`의 기존 스크립트에 추가하고, 진행률 계산은 기존 `updateReadingProgress`와 같은 식을 공유합니다.

## 구현 단계

1. [완료] `src/lib/readingPosition.mjs`(`parseStore`, `recordPosition`, `getResumeOffer`)와 단위 테스트 8개를 작성했습니다.
2. [완료] `BlogPost.astro`에 안내 마크업·스타일·스크립트를 추가했습니다. 진행률 계산은 기존 진행 표시줄 코드에서 `getReadingProgress()`로 분리해 함께 씁니다. 안내 표시 판단은 이미지가 모두 로드된 뒤(`load`) 한 번 합니다. 글 길이와 브라우저의 스크롤 복원이 그때 확정되기 때문입니다.
3. [완료] `e2e/resume-reading.spec.mjs`에 브라우저 테스트 3개를 추가했습니다. 1280px·390px, 라이트·다크 네 조합을 캡처해 확인했습니다.
   - 확인 중 390px에서 "읽던 위치가 있습니다"가 말줄임으로 잘리는 문제를 발견했습니다. 안내 문구를 첫 줄에 온전히 두고, 제목은 둘째 줄에 작은 글씨로 두어 제목만 말줄임 처리하도록 바꿨습니다. 그래서 설계의 "· <제목>" 표기는 줄바꿈 표기로 대체되었습니다.

## 테스트 설계

- 10% 미만은 저장하지 않고, 95% 이상은 기록을 지우는지
- 30개 초과 시 가장 오래된 기록부터, 90일 지난 기록이 정리되는지
- 표시 조건(기록 없음, 만료, 범위 밖)에서 안내를 제안하지 않는지
- 깨진 JSON이나 예상 밖 형식의 저장값을 빈 기록으로 다루는지
- 브라우저: 중간까지 스크롤 후 다시 열면 안내가 뜨고, "이어 읽기"로 해당 위치에 가는지
- 브라우저: `#제목` 주소로 열거나 닫기를 누르면 안내가 없는지
