# 31. 이미지 파이프라인

## 현재 동작

- 공유 이미지는 `public/images/`에 두고 `/images/...` 절대 경로로 참조합니다. 이 경로의 파일은 변환 없이 `dist/images/`로 복사됩니다(2026-10-16 기준 55개, 7.6MB).
- 글 전용 이미지는 글 옆 `images/` 폴더에 두고 상대 경로로 참조합니다(`docs/image-management.md`).
- 2026-10-16 빌드 산출물에서 본문 이미지 `<img>` 태그에는 `width`·`height`·`loading`·`decoding` 속성이 없고, WebP·AVIF 대체본도 없습니다.
- 가장 큰 단일 이미지는 `/images/Mine/20241115_112606.jpg`로 1,968,556바이트입니다.
- `check:content`는 alt 텍스트 누락을 경고하고 깨진 이미지 참조를 검사합니다. 크기·포맷은 검사하지 않습니다.
- `sharp`는 이미 의존성이며 OG 카드 생성에 쓰입니다.

## 목표

1. 본문 이미지의 전송량을 줄입니다.
2. 이미지 로드로 생기는 레이아웃 이동을 제거합니다.
3. 기존 이미지 URL과 참조 방식을 깨뜨리지 않습니다.

## 범위

- 빌드 시 본문 이미지의 치수 주입과 `loading`·`decoding` 속성 적용
- 과대 이미지의 리사이즈와 WebP 대체본 생성
- 이미지 크기 상한 경고
- 모든 이미지를 `astro:assets`로 이전하는 작업은 포함하지 않음

## 설계 방향

- 치수 주입은 remark/rehype 단계에서 원본 파일의 실제 크기를 읽어 적용합니다. 본문 Markdown은 수정하지 않습니다.
- 리사이즈·포맷 변환은 빌드 단계에서 생성하고 원본 경로는 유지합니다. `<picture>` 대체본을 추가하는 방식과 원본만 축소하는 방식을 1단계에서 비교합니다.
- 상한을 넘는 이미지는 먼저 경고로 알리고, 사람이 교체 여부를 판단합니다.
- 25번 계획으로 미참조 자산을 정리한 뒤에 변환 대상을 정합니다. 미참조 파일을 변환하는 비용을 피합니다.

## 변경 후보

- `astro.config.mjs` — rehype 플러그인 등록
- `src/lib/`(신규) — 치수 주입 플러그인
- `scripts/`(신규) — 이미지 변환·리포트 스크립트
- `scripts/lib/content-rules.mjs`, `scripts/check-content.mjs` — 크기 상한 경고
- `scripts/check-build-artifacts.mjs` — 산출물 이미지 속성·용량 검사
- `docs/image-management.md` — 규칙 반영

## 구현 단계

1. [미착수] 현재 이미지의 해상도·용량 분포를 집계하고 상한 후보를 정합니다.
2. [미착수] 치수·`loading`·`decoding` 주입 플러그인과 단위 테스트를 추가합니다. 전송량 변화 없이 레이아웃 이동만 먼저 제거합니다.
3. [미착수] 상한 초과 이미지 경고를 추가합니다.
4. [미착수] 변환 방식을 결정하고 대상 이미지에 적용합니다. 콘텐츠 자산 변경은 코드 커밋과 분리합니다.
5. [미착수] 산출물 검사와 문서를 갱신하고 전후 용량을 기록합니다.

## 테스트 설계

- 상대 경로·절대 경로 이미지 모두에 치수가 주입되는지 확인
- 치수를 읽을 수 없는 이미지에서 빌드가 실패하지 않고 속성만 생략되는지 확인
- 이미 `width`·`height`가 있는 HTML `<img>`를 덮어쓰지 않는지 확인
- alt 텍스트·lightbox 동작이 유지되는지 확인
- SVG·GIF 등 변환 대상이 아닌 포맷의 처리 확인

## 검증

- `npm run build` 및 `npm run check:build-artifacts`

- 외부 이미지 CDN
- 원본 이미지 삭제(25번 계획에서 사람이 확인한 항목만 정리)
- OG 카드 생성 방식 변경(8번·11번 계획 범위)
