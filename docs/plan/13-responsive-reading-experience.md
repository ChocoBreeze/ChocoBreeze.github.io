# 13. 반응형 읽기 경험

## 현재 동작

- 글 상세 목차는 `min-width: 1400px`에서만 표시됩니다.
- 데스크톱 목차는 현재 섹션 강조를 지원하고, 글에는 맨 위로 버튼과 이미지 확대 기능이 있습니다.
- 예상 읽기 시간과 전체 읽기 진행률은 없습니다.

## 목표

- 모바일과 노트북에서도 긴 글의 구조를 탐색할 수 있게 합니다.
- 글 길이를 읽기 전에 가늠하고 현재 읽기 위치를 확인할 수 있게 합니다.

## 권장 설계

1. 기존 `headings` 데이터를 재사용해 본문 상단에 접이식 모바일 목차를 제공합니다.
2. 데스크톱 목차와 모바일 목차는 동일한 링크 목록과 현재 섹션 상태를 공유합니다.
3. Markdown 본문에서 한국어 문자·일반 단어·코드 블록을 분리해 읽기 시간을 계산하는 순수 함수를 둡니다.
4. 진행률은 문서 전체가 아니라 글 본문 시작과 끝을 기준으로 계산합니다.

## 변경 후보

- `src/layouts/BlogPost.astro`
- `src/pages/blog/[...slug].astro`
- `src/components/BlogPostCard.astro` — 목록 표시를 선택할 경우
- `src/lib/readingTime.*` — 읽기 시간 계산을 분리할 경우
- `src/styles/global.css`

## 구현 단계

1. 대표적인 한국어·영문·코드 중심 글을 읽기 시간 계산 표본으로 선정합니다.
2. 계산 규칙과 최소 표시값을 확정하고 순수 함수로 구현합니다.
3. 글 상단에 읽기 시간을 표시합니다.
4. 1400px 미만 화면에 접이식 목차를 추가합니다.
5. 기존 IntersectionObserver 또는 스크롤 계산을 공통화해 두 목차의 활성 항목을 동기화합니다.
6. 본문 범위를 기준으로 진행률 바를 추가합니다.
7. `prefers-reduced-motion`에서 불필요한 애니메이션을 줄입니다.

## 테스트 설계

- 빈 본문, 매우 짧은 글, 한국어 장문, 코드 블록 중심 글의 읽기 시간 결과 확인
- 제목이 없는 글에서는 목차 컨트롤이 나타나지 않는지 확인
- 360px, 768px, 1399px, 1400px 이상에서 목차 전환 확인
- 목차 열기·닫기와 항목 이동을 키보드로 확인
- 스크롤 시작·본문 중간·본문 끝에서 진행률 경계값 확인
- `npm run check`, `npm run build`, `npm run format:check`

## 리스크

- 한국어 읽기 속도는 개인차가 크므로 “정확한 시간”이 아닌 추정치로 표시합니다.
- 목록 카드까지 읽기 시간을 표시하면 카드 밀도가 높아질 수 있으므로 글 상세 적용 후 별도로 판단합니다.
