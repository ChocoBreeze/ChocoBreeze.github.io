# 21. 검색 접근성과 인덱스 확장성

## 현재 동작

- 검색은 제목·설명·태그·소제목·본문 요약에 가중치를 적용합니다.
- 카테고리별 글 검색 인덱스와 별도 코드 검색을 제공합니다.
- 최근 빌드 기준 `search.json`은 약 4.26MB, `code-search.json`은 약 2.44MB입니다.
- 전역 `Cmd/Ctrl+K` 검색 팔레트는 없습니다.

## 목표

1. 어느 페이지에서든 검색을 빠르게 열 수 있게 합니다.
2. 사용하지 않는 대형 인덱스를 불필요하게 받지 않게 합니다.
3. 현재의 한국어 가중치 검색과 코드 검색을 보존하면서 확장 전략을 결정합니다.

## 권장 단계

### 1단계 — 측정과 빠른 접근

- 빌드마다 전체·카테고리·코드 인덱스 크기를 기록합니다.
- `Cmd/Ctrl+K` 팔레트에는 제목·카테고리·URL만 담은 소형 인덱스를 검토합니다.
- 팔레트를 열기 전에는 검색 인덱스를 내려받지 않습니다.

### 2단계 — 현재 검색 최적화

- 카테고리 인덱스 재사용
- 본문 검색 길이와 중복 필드 조정
- 코드 인덱스는 코드 검색 모드에 진입할 때만 로드
- 캐시 헤더는 GitHub Pages가 허용하는 범위에서 확인

### 3단계 — 대안 벤치마크

Pagefind는 다음 항목을 같은 질의 세트로 비교한 뒤에만 채택합니다.

- 한국어 부분어·띄어쓰기·복합어 결과
- 제목·태그 가중치
- 코드 검색 보존 방법
- 초기 전송량과 첫 결과 시간
- 카테고리 필터와 결과 스니펫

- `src/components/Header.astro`
- 신규 검색 팔레트 컴포넌트
- `src/pages/search.astro`
- `src/pages/search.json.ts`
- `src/pages/code-search.json.ts`
- `src/pages/search/[category].json.ts`
- `src/lib/searchIndex.ts`, `src/lib/codeSearchIndex.ts`
- 검색 크기 측정 스크립트와 테스트

## 테스트 설계

- 한글·영문·티커·코드 구문 대표 질의의 기대 상위 결과 고정
- 1자·2자·공백·특수문자·결과 없음 입력
- 팔레트 열기 전 네트워크 요청이 발생하지 않는지 확인
- 포커스 트랩, Escape 닫기, 원래 요소로 포커스 복귀
- 카테고리 변경 중 요청 순서가 뒤바뀌는 경우
- 인덱스 로드 실패와 재시도 UI
- production 빌드에서 인덱스 크기 기록
- `npm run check`, `npm run build`, `npm run format:check`

## 완료 판단

- 검색 엔진 교체 자체를 완료 조건으로 삼지 않습니다.
- 현재 기능을 유지하면서 초기 전송량과 접근 단계가 줄어들면 목표를 달성한 것으로 봅니다.
